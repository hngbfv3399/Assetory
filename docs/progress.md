# 프로젝트 진행 현황

최종 갱신: 2026-08-04
기준 문서: Notion 개발 관리·API 설계·DB 흐름, 로컬 코드·Git 이력·실제 검증 기록

## 전체 요약

- 기획·ERD·API 설계와 백엔드 도메인 API(인증, 상품, 보관, 주문·Mock 결제, 자료 접근, 상호작용, 공동 작업자, 통계)는 구현·핵심 검증을 마쳤다.
- React는 공개 상품 탐색(목록·검색·정렬·상세·후기)과 홈·주요 기능·가격 정책·로그인 화면의 기본 UI를 갖췄다.
- 로그인·판매자 상품 등록·구매자 장바구니·Mock 결제·라이브러리의 기본 흐름은 React API 연결을 시작했다. 판매 후 운영·공동 작업자 화면은 아직 데모 UI가 남아 있다.
- 따라서 현재 프로젝트의 완료 기준은 **백엔드 API 완성**이 아니라, 판매자 등록부터 구매자 다운로드·판매자 운영까지의 React 통합과 배포 환경 종단 검증이다.
- 10단계는 문서·자동 검증·프론트 공개 화면까지 진행됐고, 실제 배포와 운영 화면 구현이 남아 있다.

## 구현 순서 결정

- 백엔드 우선 구현 전략은 완료됐다. 이제 React를 기능 목록 단위가 아니라 **한 번에 시연 가능한 사용자 흐름** 단위로 연결한다.
- 권장 순서: 실제 인증 → 판매자 상품 등록·판매 시작 → 구매자 찜·장바구니·Mock 결제·라이브러리 → 판매자 주문·문의·환불·통계·공동 작업자 → 배포 환경 종단 검증.
- 실제 PG 결제·송금 정산·배송은 범위 밖이다. 결제는 Mock, 정산은 수수료 10% 기반 예상 금액 표시만 제공한다.

## 다음 세션 인수인계

### 현재 기준선

- 현재 브랜치: `main`. 공개 안내 페이지와 모바일 레이아웃 개선은 `01f856c`, 디자인 규칙 문서는 `d7fcee1`에 기록되어 있다.
- `d7fcee1`은 이 문서 갱신 시점에 원격 `origin/main`보다 앞서 있으므로, 다음 원격 반영 전에 함께 푸시 여부를 확인한다.
- Notion 일정의 2·4·5단계 비고는 백엔드 완료·React UI 보류를 이미 구분한다. 10단계는 아직 `시작 전`으로 남아 있으며, 외부 일정 상태 변경은 별도 사용자 승인 후에만 `진행 중`으로 동기화한다.
- 프론트 최근 검증: `cd frontend && npm run lint && npm run build` 통과.
- 백엔드 핵심 검증 기록: Maven 테스트, 인증 흐름, 공동 작업자 15단계 종단 스크립트가 로컬 환경에서 통과했다. 이번 문서 갱신에서는 전체 백엔드 테스트를 다시 실행하지 않았다.
- 작업 트리에 `ProductAccess.java`, `ProductAccessRepository.java`의 미커밋 포맷 정리 변경이 남아 있다. 기능 변경으로 취급하거나 다른 작업과 섞지 말고, 필요 시 별도 검토·커밋한다.

### 이미 화면에 있는 범위

- 공통 다크 브랜드 헤더·푸터
- 홈(`/`), 주요 기능(`/features`), 가격 정책(`/pricing`)의 안내·브랜드 화면
- 공개 탐색(`/products`)과 상품 상세·후기(`/products/:productId`) API 연결
- 로그인(`/login`) UI. 단, 현재는 Mock 성공 처리이므로 인증 API와 연결되어 있지 않다.
- 디자인 작업은 [design-guidelines.md](design-guidelines.md)를 기준으로 한다. 특히 320px·390px·1280px 검수, 한글 줄바꿈, 모바일 카드 정보 폭, 모션·접근성 규칙을 따른다.

### 다음 구현 순서와 완료 조건

1. **판매자 상품 관리 화면 보완**
   - 상품 수정·이미지·자료 삭제·판매 중지, 판매자 주문·통계 화면을 실제 API에 연결한다.
   - 완료 조건: `DRAFT` 생성부터 공개 상품 탐색 노출까지 브라우저에서 검증한다.
2. **구매자 구매 흐름 보완**
   - 찜, 다운로드 리다이렉트, 오류 상태·주문 상세를 연결한다.
   - 완료 조건: 비회원 탐색 → 로그인 → 장바구니 → Mock 결제 → 자료 이용을 브라우저에서 검증한다.
4. **판매 후 운영 화면**
   - 주문, 환불, 문의 채팅, 후기, 판매 통계·예상 정산, 공동 작업자·변경 요청을 순서대로 연결한다.
   - 완료 조건: 판매자와 구매자의 권한 차이, 환불 후 접근 회수, 공동 작업자 승인 정책을 화면에서 검증한다.
5. **통합·배포**
   - 배포 대상과 운영 MySQL·환경변수를 확정한 뒤, 실제 URL에서 인증·구매·자료 접근·권한 흐름을 검증한다.

### 구현 시 주의할 기술 부채

- `frontend/src/api/catalog.js`는 현재 별도 `fetch` 래퍼를 사용한다. 새 기능을 추가하기 전 또는 인증 연결과 함께 `src/common/api/fetchClient.js`로 통일해 프론트 구조 규칙을 지킨다.
- 새 API 호출은 `Page → 페이지 전용 Query Hook → 페이지 전용 API 함수 → fetchClient` 흐름을 유지한다. Page에서 직접 `fetch`하지 않는다.
- `spring.jpa.hibernate.ddl-auto=update`는 운영 배포 전 스키마·백업·마이그레이션 전략을 검토해야 한다.
- Notion 단계별 진행률은 “백엔드 구현”과 “React UI까지 포함한 사용자 기능”을 구분해 기록한다. API만 완료됐다고 전체 단계를 완료로 변경하지 않는다.
