## 추가 작업 — 계층형 카테고리 탐색

- 기존의 평면 카테고리를 상위 분류와 세부 분류로 확장했다. 상위 분류는 디자인·개발·전자책을 유지하고, UI/UX·게임 에셋·아트·일러스트·영상·모션·웹·앱 템플릿·코드·라이브러리·프로그램·도구·판매·운영 가이드·영상 강의·비즈니스 자료를 추가했다.
- `categories.parent_id`를 JPA 로컬 스키마 갱신으로 추가했고, 로컬 시더가 기존 100개 Mock 상품을 세부 분류에 재배치하도록 구성했다. 상품을 삭제하지 않았고, 기본 개발 DB에서 실제 반영했다.
- `GET /api/categories`는 상위 분류와 `children` 목록을 반환한다. `GET /api/products?categoryId=`는 세부 분류뿐 아니라 상위 분류 선택 시 그 하위 상품까지 함께 조회한다.
- 상품 탐색 화면은 상단의 큰 분류 카드와 왼쪽 세부 분류 필터로 구성했다. 390px에서는 가로 스크롤 가능한 세부 분류 영역으로 전환한다.
- 실제 API에서 디자인 상위 분류 48개, UI/UX 세부 분류 10개를 확인했고, 브라우저에서 세부 분류 클릭 시 URL과 상품 수가 함께 변경되는 것을 확인했다.
- `.env`를 로드한 `cd backend && ./mvnw test`에서 애플리케이션 컨텍스트와 판매자 주문 서비스 테스트를 포함한 2건이 모두 통과했다.

## 판매자 스튜디오 화면 설계 반영 (2026-08-05)

- Gumroad의 좌측 앱 네비게이션 구조와 Notion의 판매자·공동 작업자 요구사항을 비교해 `/seller`를 공개 스토어와 분리된 판매자 스튜디오로 재구성했다.
- Home, Products, 새 상품, 상품 상세, Sales, 예상 정산 화면을 같은 앱 셸 안에 배치했다. 판매자 영역에서는 공개 스토어의 공통 헤더·푸터를 표시하지 않는다.
- Products는 전체 상품·내 소유·공동 작업 상품 범위와 상태를 보여 주고, 상품 상세에서는 개요·기본 정보·이미지·구매 자료·공동 작업자·변경 요청·운영 탭을 제공한다.
- 공동 작업자는 상품 단위로 표시한다. 소유자는 승인·초대 권한을, 매니저는 판매·운영 요청 권한을, 편집자는 상품 정보·이미지·구매 자료 변경 요청 권한을, 뷰어는 통계 열람 권한을 가진다는 현재 API 계약을 화면에 반영했다. 변경 요청의 최종 승인·반려 권한은 소유자에게만 둔다.
- Sales에는 주문·문의·환불 운영 진입점과 빈 상태를, 예상 정산에는 결제 완료 매출·환불 차감·플랫폼 수수료(10%)의 계산 구조와 추이·상품별 판매 영역을 배치했다. 실제 송금은 범위 밖임을 명시했다.
- 로그인 및 실제 판매자 API 연결 전 단계이므로, 상품·팀·요청·집계는 화면 검토용 데모 데이터이며 버튼은 데이터를 변경하지 않는다.
- 1280px에서 공동 작업자·판매 운영·예상 정산 화면을, 390px에서 공동 작업자 화면을 확인했다. 모바일은 좌측 메뉴가 상단 가로 목록으로 전환되며, 콘텐츠는 한 열로 표시된다.
- `cd frontend && npm run lint`, `cd frontend && npm run build`를 통과했다.

## 판매 등록 편집기·구매자 공개 페이지 미리보기 (2026-08-05)

- 판매자 상품 등록과 기본 정보 탭을 하나의 편집기 흐름으로 정리했다. 상품 유형, 세부 카테고리, 상품명, 한 줄 소개, 판매 가격, 이용 조건을 작성할 수 있다.
- 상세 설명은 Markdown으로 작성한다. 제목(`#`~`###`), 목록, 굵은 글씨, 링크, 구분선의 안전한 미리보기를 제공하며, 빠른 입력 도구와 문법 도움말을 추가했다. 임의 HTML을 렌더링하지 않는다.
- 편집기 오른쪽에는 입력값이 즉시 반영되는 구매자용 축소 미리보기를 두고, 상품 상세의 `구매자 미리보기` 탭에서 전체 공개 상품 페이지 구조를 확인할 수 있게 했다.
- 공개 페이지는 Gumroad 상품 상세의 정보 우선 구조를 참고해 대표 미리보기, 카테고리·상품명·한 줄 소개·가격·Mock 결제 CTA, Markdown 설명, 포함 자료·이용 조건·판매자 정보를 순서대로 구성했다.
- 판매·정산·공동 작업자·변경 요청·이미지·구매 자료 화면은 앞선 판매자 스튜디오에 포함되어 있으며, 인증·실제 판매자 API 연결 전에는 데모 데이터와 비저장 버튼으로 동작한다.
- 1280px에서 편집기와 전체 공개 미리보기를, 390px에서 상품 등록 화면을 확인했다. 390px에서 문서 가로 넘침 없이 한 열 편집 흐름과 미리보기 영역이 표시됐다.

- 상위 분류 버튼을 선택하면 해당 세부 분류 select가 즉시 교체되고, 선택값은 구매자 미리보기의 카테고리 표기에 반영된다. API를 아직 불러오는 순간에도 같은 8개 분류의 안전한 기본 목록을 표시한다.
- 브라우저에서 3D 버튼 클릭 뒤 세부 분류가 `3D 모델`로 바뀌고 미리보기에도 `3D · 3D 모델`로 반영되는 것을 확인했다.

## 인증 역할 설계·가상 계정 검증 (2026-08-05)

- 회원가입 시 구매자·판매자를 나누어 선택하지 않고, 활성 회원 누구나 상품 등록을 할 수 있도록 전역 `BUYER`·`SELLER` 역할 모델을 제거했다. 판매자 판별은 상품 `seller_id` 소유권, 공동 작업자 판별은 상품별 협업 권한으로 수행한다.

## 판매자·구매자 2계정 종단 흐름 검증 (2026-08-05)

- 로컬 DB에 서로 다른 판매 흐름·구매 흐름 테스트 계정을 각각 가입시키고 로그인 JWT 발급을 확인했다. 테스트 비밀번호·토큰은 기록하지 않았다.
- 판매 흐름 계정이 상품 초안 생성, 대표 이미지와 구매 자료 등록, 판매 시작을 수행했고 상품은 `ON_SALE` 상태가 됐다. 비회원 공개 상품 상세 조회도 `200`으로 확인했다.
- 구매 흐름 계정이 해당 상품을 직접 주문하고 Mock 결제를 성공 처리했다. 주문은 `PAID`가 되었고 구매 목록·구매 자료 조회·자료 열기까지 모두 `200`을 반환했다.
- 구매 흐름 계정이 판매자 상품 상세를 직접 관리하려 하면 `403`으로 차단됐다. 반면 전역 판매자 역할을 없앤 정책대로 판매자 상품 목록 자체는 `200`과 빈 목록을 반환했다.
- 백엔드 API 흐름은 동작하지만 React에서는 구매자 장바구니·주문·결제·라이브러리와 판매자 등록의 이미지·구매 자료·판매 시작을 아직 실제 API에 연결해야 한다. 판매 방식(멤버십·선주문·가격 자율 설정)도 현재 화면 설계용이며 단일 가격 즉시 구매 API만 실제 처리한다.
